# AP/2717 design direction

Product: a public profile for a student building backend and applied AI systems.
Character: observant, grounded, curious.
World: weathered stone, forested cliffs, running water, and the traces left by real software work.
Moments: a title sequence and one second establishing shot; the rest is a readable technical field guide.
Signature: traceable decisions. Claims, event groups, notification actions, and model feedback each show the path from input to output.

## Audit and decisions

- Previous floating platforms and identical panels were repetitive. Replace them with an evidence review, a clustering visualization, a routing ledger, a deployment trace and a request/response animation.
- No glass overlays, gradient typography, neon halo, fake status lights, badges, floating rectangles, decorative orbit or repeating numbered headings. The only gradients outside real artwork are physical title shading and feathered mist.
- Use one dark or light neutral ramp, muted green for a data path, warm brass where a distinct result requires contrast, and two type families plus monospace for measured data.
- Keep skills and project explanations as native Markdown; no important information depends on small SVG text.
- Environment motion comes from localized, feathered water masks and particles. Keep the camera and nameplate fixed. All moving technical marks show conceptual processing, not production service status.
- Motion is an enhancement: reduced-motion rules, static text, and no scripts or external image requests in SVGs.
- Retain three documented projects and authentic GitHub calendar data. Do not invent certifications, proficiency percentages or uptime.
- Review images in a browser at README width and on a phone-sized viewport; verify motion between captures and static fallback, check links and build tests. Do not claim cinematic playback in a user's particular browser without observing it.
